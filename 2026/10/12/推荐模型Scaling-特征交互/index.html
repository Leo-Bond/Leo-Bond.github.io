推荐模型 Scaling（二）：从显式特征交互到 TokenMixer

发表于 2026-10-12 更新于 2026-10-13 分类于 推荐系统
对比 DHEN、Wukong、RankMixer 与 TokenMixer-Large 的交互机制，解释逐层内积、固定 Token Mixing、Mixing–Reverting 与 GPU 执行优化的不同作用。

把推荐排序网络做大，可以增加 MLP 宽度，也可以增加交互轮数，或者为每个 Token 配置独立网络。这些方案都会增加参数，却不一定增加同一种建模能力。

Interaction Scaling 关注的是：Embedding 已经查出来以后，用户、候选和上下文特征如何持续交换信息，并让新增计算在 GPU 上高效执行？ 本篇用 DHEN、Wukong、RankMixer 和 TokenMixer-Large 说明四种不同取舍。

来源与公式说明：本文依据《推荐模型 Scaling：为什么必须依赖 Model–System Co-design》第二章整理。公式仅按原文明确的文字关系重建，省略归一化等未完整导出的细节，不是论文原式或可直接复现的实现。论文结果均为综述转述，未逐篇重新核验。

  1. 总览：参数、计算与系统约束

1. 先区分输入字段与 Feature Token

User ID、Item ID、Category、Context 等输入项，可以看作语义固定的特征字段。一条样本为每个字段填入具体取值，经 Lookup 或投影得到向量。

在解释交互主干时，可以把输入简化为 n 个 d 维向量：

\[ X\in\mathbb{R}^{n\times d}. \]

这里省略 Batch 维。需要注意，一个 Feature Token 不一定等于一个原始字段。有的模型先将数百个字段按语义组织，再投影成较少的 Token。

扩展不同模块，含义也不同：

操作 主要增加的计算或容量
加宽 MLP 对输入表示进行更宽的非线性变换
增加 Cross Layer 增加显式交叉的轮数
增加 Attention 层 增加输入相关的 Token 间信息聚合
增加 Expert 总数 增加存储容量；活跃计算还取决于路由
增加重复交互 Block 取决于 Block 内部究竟执行什么

所以，对比模型时应先看“每一层如何更新表示”，再看参数和 FLOPs。

2. DHEN：每层组合不同的交互模块

2.1 从选择一个模块，到组合多个模块

传统方案往往先选择 DCN、Attention 或 FM 等某一种主要结构，再增加宽度和深度。DHEN 采用另一种思路：不同模块各有侧重，不必把所有交互都交给同一种结构。

原文列举的模块包括 AdvancedDLRM、Self-Attention、Convolution、Linear Module 和 DCN。其中 AdvancedDLRM 是论文对一类采用 DLRM 式交互的工业模块的称呼，不应误解为统一的软件接口。

根据原文的模块聚合与 Shortcut 描述，可将一层抽象为：

\[ Z_l^{(m)}=f_l^{(m)}(X_l),\qquad X_{l+1}=\operatorname{Aggregate}_l \left(\{Z_l^{(m)}\}_{m\in\mathcal{M}_l}\right) +\operatorname{Shortcut}_l(X_l). \]

这里 Aggregate 仅表示经形状对齐后的聚合操作，不指定原文未导出的具体实现。各分支读取同一层输入；下一层处理的是本层聚合后的结果，而不是所有模块永远只处理最初特征。

2.2 扩大的是交互组合，而不只是 MLP

原文转述的一组比较中，DHEN 每层组合 AdvancedDLRM 和 Linear Module，在相近训练 FLOPs 下优于仅通过 MoE 扩大 AdvancedDLRM 内部 MLP 的方案。

合理结论是：在该测试配置中，反复组合异构交互比只扩大基线内部 MLP 更有效。 这不能推出所有场景都应该使用全部交互模块。

2.3 模型变深以后，参数怎么放？

Dense 参数和反向传播需要的中间结果可能超过单卡显存。原文介绍的分层参数分片，使一台服务器内的参数聚合与梯度切分主要使用 NVLink，不同服务器再同步对应分片的梯度。

它解决的是训练可执行性，并没有把 Self-Attention、DCN 和卷积自动变成同一种算子。模块异构性仍然存在，系统需要承担相应调度与中间数据成本。

3. Wukong：每层重新计算显式交互

3.1 一次交互与多轮交互有什么不同？

如果模型只在入口计算一次两两内积，随后一直堆叠 MLP，那么增加的主要是对已有交互结果的非线性变换。

Wukong 的 Factorization Machine Block（FMB）则在每层重新计算当前向量之间的内积，再把结果编码为新向量，交给下一层继续交互。

设第 l 层输入为 n_l 个 d 维向量，根据原文定义：

\[ X_l\in\mathbb{R}^{n_l\times d},\qquad G_l=X_lX_l^\top\in\mathbb{R}^{n_l\times n_l}. \]

G 中每个元素都是当前两个向量的内积。FMB 将内积结果编码为一组新向量；另一条 Linear Compression Block（LCB）沿向量数量维度做线性重组，不经过两两内积。

下一层基于更新后的向量重新计算交互。因此，加深 Wukong 不只是多加几层 MLP，还增加了显式交互轮数。

这里的 FMB 也不同于把二阶交互直接求和作为预测项的经典 FM：它保留交互结构，再学习输出表示。

3.2 避免显式保存完整内积矩阵

完整 G 的元素数随 n_l 的平方增长。原文介绍了压缩投影和调整矩阵乘法顺序的做法。用解释性维度约定表示，令 P 为 n_l×r 的投影矩阵：

\[ \widetilde{G}_l=(X_lX_l^\top)P =X_l(X_l^\top P),\qquad P\in\mathbb{R}^{n_l\times r}. \]

这个等式来自矩阵乘法结合律。右侧可以先计算较小的中间结果，避免显式物化 n_l×n_l 矩阵。它解释的是原文的优化思想，不宣称完整复现 FMB 的所有实现细节。

Wukong 的规模变量包括交互层数、FMB/LCB 输出向量数、压缩维度和内部 MLP 宽度。低秩压缩降低成本，但没有取消每层的显式交互计算。

4. RankMixer：固定重排加独立 FFN

4.1 为什么不继续堆更多交叉模块？

RankMixer 更关注 GPU 执行效率。大量小型 MLP、Attention、Gate 和人工交叉模块组合后，可能使执行路径碎片化。

它把交互拆成两个步骤：

  1. Multi-head Token Mixing：用固定 Split–Concat 交换向量片段；
  2. Per-token FFN：不同 Token 使用独立参数，承担主要非线性建模。

原文介绍的 100M 与 1B 配置分别使用 16 和 32 个 Feature Token。这里的 Token 是组织后的特征块，不是每个字段单独对应一个 Token。

每个片段具有相同维度，每个 Mixed Token 都得到所有输入 Token 的一部分信息。

这个操作不计算 Attention Score，也不产生依赖当前样本的两两权重。它没有可学习参数，但重排仍可能涉及内存搬运，并不等于零成本。

设输入 Token 数为 T，每个 Token 维度为 D，切为 H 份，则重排前后形状为：

\[ [B,T,D]\longrightarrow[B,H,TD/H],\qquad H\mid D. \]

原始 RankMixer 取 H=T，使重排结果与输入形状一致。忽略归一化后，可用下式说明两个残差步骤：

\[ S=X+\operatorname{Mix}(X),\qquad Y=S+\operatorname{PFFN}(S). \]

PFFN 表示每个 Token 位置拥有独立参数的 FFN。固定重排负责交换信息，FFN 负责学习非线性关系；不能把前者“无参数”推广成整个模型不需要学习。

4.3 为什么 Per-token FFN 有利于扩容？

不同 Token 的 FFN 参数独立，但计算形状相同，可以用 Grouped GEMM 组织执行。网络还可以扩展为 Per-token Sparse MoE，以较大的 Expert 集合增加总容量，同时控制活跃计算。

原文转述的一组生产结果中，参数从约 1600 万增加到约 11 亿，FLOPs 增加约 20 倍，MFU 从约 4.5% 升到约 44.6%，线上延迟基本持平。

这不是“参数可以免费增加”的证据。它来自模型结构、矩阵运算占比、执行优化和更低精度等共同变化，不能单独归因于 Token Mixing 或稀疏 MoE。具体实验口径可结合站内 RankMixer 专题 阅读。

5. TokenMixer-Large：恢复布局，再做跨 Block 残差

5.1 形状相同不意味着 Token 语义对齐

前面的例子里，x1 来自第一个 Feature Token，s1 却包含三个 Feature Token 的第一段。原始 RankMixer 可以直接相加，因为维度相同；但残差两侧的片段来源不再一一对应。

这不是张量运算上的非法操作，而是一种结构取舍。原文将它视为 TokenMixer-Large 要改善的问题。同时，H=T 还把两个本可以独立决定的量绑定了：输入 Token 数与内部 Mixed Token 数。

5.2 Mixing–Reverting 如何解开绑定？

用三个输入 Token、两个内部 Token 表示：

Reverting 将两个内部 Token 重新组织为三个外部位置。这里“恢复”是恢复布局与位置对应关系，不是撤销已经发生的非线性变换，更不是恢复原始数值。

根据原文描述，省略归一化等细节，一个 Block 可以概括为：

\[ M=\operatorname{Mix}(X),\qquad U=M+\operatorname{PSwiGLU}_{\mathrm{mix}}(M), \] \[ V=\operatorname{Revert}(U),\qquad Y=X+\operatorname{PSwiGLU}_{\mathrm{feature}}(V). \]

内部 Per-token 网络处理 Mixed Layout；Reverting 恢复 Feature Layout；最后的 Per-token 网络输出再与 Block 输入相加。

因此，Feature Token 数由输入组织决定，内部 Mixed Token 数可以根据网络宽度和矩阵形状选择，只需满足切分与形状约束。

5.3 扩大模型，还要解决深层训练与通信

原文还介绍了三组配套设计：

  • Sparse Per-token MoE：扩大 Expert 总量；
  • 间隔跨层残差与中间层辅助 Loss：帮助深层优化，使靠近输入的 Block 获得更直接的监督；
  • Token Parallel：沿 Token 维度切分 Per-token 参数和计算。

Token Parallel 的重点不仅是“把 Token 分到不同 GPU”。它让 Mixing–Reverting 的数据布局与分布式执行匹配，减少每层反复在 Batch Sharding 和 Token Sharding 之间转换的通信。

这说明并行方案不是模型完成后的外部包装。Token 的组织方式会影响参数如何切分，也会影响 GPU 之间需要交换什么。

6. 四类方法并不是一条替代链

方法 信息如何交互 主要扩展方向 系统落点
DHEN 每层并行组合异构模块 交互层数与模块容量 参数分片、异构执行
Wukong 每层重新计算显式两两内积 层数、输出向量数、压缩维度、MLP 避免物化完整内积矩阵
RankMixer 固定重排后做独立 FFN Token、宽度、层数、Expert 规整 GEMM、融合、低精度
TokenMixer-Large Mixing 后计算，再 Reverting 内部 Token、深度、Expert 深层训练、布局匹配的 Token Parallel

Wukong 的显式两两内积与 RankMixer 的固定片段重排不是同一类交互。前者显式构造当前向量间关系，后者通过固定信息流让后续非线性网络学习关系。

同样，DHEN 不应该被描述为必然落后的阶段。它保留异构模块的建模偏置；是否适合某个业务，要看数据、效果和执行成本。

7. 如何判断该把交互网络扩大到哪里？

可以分三步进行实验：

  1. 控制输入与数据：保持特征、历史编码和训练样本一致，先比较交互机制。
  2. 分别扩大变量：层数、宽度、Token 数和 Expert 总量分开考察，报告活跃计算。
  3. 测量实际执行：不仅统计 FLOPs，还测训练吞吐、MFU、显存、通信和线上延迟。

一个更大的 MLP 不一定比多一轮有效交互更好；一个更复杂的交互模块，也可能因访存和小算子成本而无法上线。最有价值的结果是：新增交互既改善预测，又能转化成可执行的计算。

本篇处理的是一组已经读出的推荐特征。下一篇 Sequence Scaling 将把输入扩大到用户长期历史，并讨论为什么“历史缓存了”仍不意味着多候选打分没有成本。
