Cluster GOOBS：基于语义聚类的实时困难负采样

发表于 2026-10-12 分类于 推荐系统
解读 Cluster GOOBS 如何通过语义聚类与实时特征池增强双塔负采样，分析 Softmax 梯度、混合采样比例、哈希更新及公开实验与线上 CTR 的结论边界。

双塔召回模型的训练效果，不仅取决于用户塔和物品塔有多复杂，也取决于模型每天需要区分什么。如果负样本始终是明显不相关的物品，训练损失可以很快下降，但模型未必学会在相似内容之间做细粒度选择。

Cluster GOOBS 把这个问题拆成两部分：用语义聚类缩小负样本的搜索范围，再用实时维护的物品特征池低成本地提供样本。它没有把 LLM 放到每次推荐请求中，而是用 LLM 衍生的内容表示改善双塔的训练数据组织。

论文：Ivan Ji, Liuyi Hu, Harrison (Zihao) Zhao, et al. Real-Time Hard Negative Sampling via LLM-based Clustering for Large-Scale Two-Tower Retrieval. arXiv:2607.00448, 2026。HTML 正文 · PDF

本文从一份论文汇报出发，并核对了论文公开正文和实验表。论文结果与本文分析分别标注；数学符号统一整理，梯度推导用于解释，不代表额外的实验复现。内容核对日期为 2026-10-12。

1. 负采样究竟改变了什么？

1.1 双塔把召回转化为向量检索

设用户信息为 x，物品信息为 y，用户塔和物品塔分别输出向量 u 和 v。以点积为例：

\[ u=f_\theta(x),\qquad v=g_\theta(y),\qquad s_\theta(x,y)=u^\top v. \]

双塔的优势是两侧独立编码：物品向量可以提前计算并建立索引，线上计算当前用户向量，再检索高分候选，而不必逐个运行复杂的用户—物品交互网络。

训练时，可以把召回写成全物品空间中的分类问题。按照论文 §3.1，令可推荐物品集合为 I：

\[ P_\theta(y_i\mid x_i) =\frac{\exp s_\theta(x_i,y_i)} {\sum_{y\in\mathcal{I}}\exp s_\theta(x_i,y)}. \]

当物品库达到千万量级，逐样本计算完整分母通常不可接受。因此训练只使用正样本与部分负样本，采样策略实际决定了模型在训练中面对的竞争集合。

1.2 In-batch 与随机 OOB 分别解决什么？

In-batch Sampling 把同一 Batch 中其他样本的正物品当作当前用户的负样本。若 Batch 包含 B 个正对，暂不考虑重复与屏蔽，每个用户得到 B−1 个负样本。

它复用了已有的物品编码，但不是“零计算成本”：仍需计算用户与其他物品的相似度以及损失。并且，负样本分布来自交互日志，出现频率较高的物品更容易进入 Batch。

随机 Out-of-Batch（OOB）Sampling 从更大的池中取物品，扩大了训练覆盖范围。然而，在训练已经有一定区分能力时，很多随机物品的分数很低，继续区分它们可能提供不了多少新增信号。

“随机负样本容易”是常见现象，不是关于所有用户、物品与训练阶段的定理。冷启动用户、噪声数据和训练初期仍可能产生不同情况。

2. 为什么困难负样本更有训练信号？

2.1 从损失看单个负样本的作用

对一个正对，令采样候选集合为 C_i，包含正物品 y_i 与负物品。为避免和采样随机数混淆，用 w_i 表示论文中的标签权重 r_i；分析一个正样本时取 w_i=1。论文 §3.2 的采样目标可整理为：

\[ \mathcal{L}_i =-w_i\log\frac{\exp z_{i,+}} {\sum_{j\in\mathcal{C}_i}\exp z_{ij}}, \qquad z_{ij}=s_\theta(x_i,y_j). \]

这个式子表达采样后的交叉熵。它本身不意味着使用任意非均匀负采样都能无偏估计全库 Softmax，也没有包含所有实际训练中的 LogQ 或 Mask 细节。

下面是本文基于该目标的推导。令候选的归一化概率为 p_ij，则对负样本的 logit：

\[ p_{ij}=\frac{\exp z_{ij}} {\sum_{k\in\mathcal{C}_i}\exp z_{ik}},\qquad \frac{\partial\mathcal{L}_i}{\partial z_{ij}}=w_i p_{ij} \quad(j\ne +). \]

对正样本则为 w_i(p_i,+−1)。在候选集合及其他分数固定时，提高某个负样本的分数，会提高它在 Softmax 中的质量，使它受到更强的向下调整。

关键是相对分数和归一化概率，而不是“相似度接近零，所以指数与梯度接近零”。例如 exp(0)=1，并不接近零；只有当它相对分母的其他项足够小，p_ij 才会很小。

2.2 Logit 梯度与参数梯度也要区分

在点积模型下，用户向量的梯度为：

\[ \frac{\partial\mathcal{L}_i}{\partial u_i} =w_i\left(\sum_{j\in\mathcal{C}_i}p_{ij}v_j-v_+\right). \]

每个负物品通过 p_ij v_j 参与更新。参数梯度还要乘上网络的 Jacobian，因此不能把“参数梯度大小”简单等同于 exp(score)。

论文 §3.3 的直觉是：与正样本语义接近的物品，更有机会成为有竞争力的负样本，促使模型学习簇内差别。语义接近只是困难度的代理，不保证同簇物品一定是当前用户的高分近邻。

2.3 困难也不是越多越好

相似内容可能确实符合用户兴趣，只是没有被曝光或点击。将它当作负样本，会产生 False Negative。

论文报告将每个正样本的簇内负样本数从 1 扩到 64 时，较少数量效果更好，更多困难负样本反而使表现下降。正文没有给出完整消融表，因此这里保留定性结论，不补写最优数量或具体降幅。

困难采样需要在区分能力、覆盖度和假负例风险之间取舍，而不是追求“所有负样本都最难”。

3. 与 LogQ、DNS、CBNS、ANCE 的关系

3.1 LogQ 纠正采样频率，不负责寻找困难样本

论文 Baseline 是 In-batch + LogQ，并对已知正例使用 False-Negative Mask。LogQ 的典型形式是：

\[ \widetilde z_{ij}=z_{ij}-\log q(y_j). \]

q 表示相应采样机制中的出现概率。更完整的采样 Softmax 实现可能使用期望采样次数，并需要区分强制加入的正样本、重复项与不同采样来源。

由于 q≤1，减去 log q 通常会提高 logit；低频项提高得更多。因此不能只把这一步解释成“把热门物品的原始 logit 减小”。它是在补偿采样频率差异，不是在线推荐阶段对热门物品直接降权。

Cluster GOOBS 又引入依赖正样本簇的采样分布。不能不加分析地把 In-batch 的边际频率用于所有 OOB 样本，也不能据一个 LogQ 式子断言已经消除了曝光偏差。

3.2 几种负采样方式的差别

方法 负样本选择依据 复用或维护什么 主要取舍
In-batch 当前 Batch 的其他物品 当前已编码物品 成本低，但数量和分布受 Batch 限制
DNS 当前模型对候选的评分 动态候选评分 有模型感知能力，成本取决于候选集合大小
CBNS 最近 Batch 中出现的物品 历史物品 Embedding 编码复用高，但向量随模型更新而陈旧
ANCE 查询在 ANN 索引中的近邻 全局索引与异步刷新 模型相关的困难度，但存在刷新和查询成本
随机 GOOBS 维护池中的随机位置 物品特征 覆盖更广，不主动筛选高分负例
Cluster GOOBS 正物品所在簇内的随机位置 按簇分段的物品特征池 避开逐步全局搜索，但困难度依赖聚类质量

需要避免三个过度概括：

  • DNS 不必每一步遍历全库。 它也可以先随机抽取一个候选子集，再选择模型评分高的物品；代价取决于具体实现。
  • ANN 近邻不是精确的全局最难负样本。 ANCE 面向查询检索近邻，并受近似搜索、索引版本和打分定义限制。
  • 无法只凭方法名称给出统一复杂度或是否“实时可用”。 ANN 的复杂度依赖索引结构与查询参数，CBNS 的陈旧程度依赖缓存和模型变化速度。

GOOBS 不需要为训练负采样维护 ANCE 式全库索引，并不意味着双塔的线上召回也不再需要向量检索索引。

4. Cluster GOOBS：用语义结构组织采样空间

4.1 先分簇，再按正样本的簇采样

对每个物品预先计算 cluster_id。训练遇到正物品 y_i 时，从同簇候选中抽取负物品，而不是逐个计算当前用户与全库物品的相似度。

这里选择的是“正物品的语义邻域”，不是“当前用户向量的模型近邻”。它用较稳定的内容结构换取便宜的候选定位，将当前模型的计算留给采样之后的编码与训练。

4.2 工业聚类与公开数据集聚类不是一回事

论文 §3.4 介绍，工业方案使用基于 LLM 的多模态内容表示，覆盖文本、图像、音频与视频，再对表示做 k-means。新物品编码后分配给最近中心。

工业配置选择了 300 个簇，98% 的簇至少包含 10,000 个物品。论文还报告，在 100 到 10,000 个簇的离线搜索范围内，250—500 个簇取得了较好的平衡。

公开实验则直接使用 MovieLens 的 genre 与 Amazon 的 category，不运行这套工业 LLM 聚类。因此：

  • 公开实验主要检验基于簇的采样机制；
  • 线上实验检验包含 LLM 表征、聚类和特征池在内的组合方案；
  • 不能据此证明 LLM 聚类一定优于类目标签，也不能把 300 个簇当成通用超参数。

4.3 混合比例：少量簇内负样本配合随机 OOB

论文 §5.1.2 明确给出：

数据集 cluster OOB : random OOB 仅在 OOB 部分中的簇内占比
MovieLens-1M 1 : 15 1/16，即 6.25%
Amazon Reviews 1 : 31 1/32，即 3.125%

这是“聚类 : 随机”，不是反过来。 OOB 之外仍有 In-batch 负样本，所以最后一列不是全部负样本中的比例。

用本文引入的混合分布表示法，可以写成：

\[ q_{\mathrm{OOB}}(y\mid y_i) =\alpha q_{\mathrm{cluster}}(y\mid c(y_i)) +(1-\alpha)q_{\mathrm{random}}(y). \]

这是对混合机制的概括，不是论文新增的损失公式。簇内部分提供细粒度竞争，随机部分保持较广的覆盖；池中的实际物品分布还受更新和哈希碰撞影响。

5. GOOBS 实时特征池怎样工作？

5.1 缓存的是 Features，不是旧模型 Embedding

GOOBS 维护预分配的槽位数组，每个槽位保存物品特征张量。采样后，特征进入当前训练模型。

这与 CBNS 直接复用旧版模型编码的向量不同：GOOBS 可以用当前物品塔重新编码，但需要支付编码成本，也仍可能读取过期的物品属性。模型向量陈旧与原始特征陈旧是两个不同问题。

设簇数为 C，每簇槽数为 S，则总槽数为 CS。不同簇拥有相同的缓存容量，不意味着不同簇中的全量物品数相同。

5.2 Update Engine：确定性映射，碰撞时覆盖

按照论文 Algorithm 1，给定物品 ID x 与簇编号 c：

\[ \operatorname{slot}(x,c)=cS+(x\bmod S), \qquad c\in\{0,\ldots,C-1\}. \]

例如 S=1000、c=7、x=12345，对应槽位是 7345。同一物品在簇和容量不变时映射到同一槽位，不会因为反复进入 Batch 而占据多个位置；不同物品可能碰撞，后写入的覆盖先写入的。

这是有界缓存，不是完整物品数据库，也不是保留所有历史物品的集合。简单取模是否均匀，取决于 ID 分布，不能由公式本身保证。

5.3 Sample Engine：定位分段后随机取槽

按照论文 Algorithm 2，对正物品所属簇 c 随机取偏移量：

\[ a\sim\operatorname{Uniform}\{0,\ldots,S-1\},\qquad \operatorname{sampleSlot}=cS+a. \]

当槽位有效、簇版本一致时，返回的物品属于该簇。读取一个位置无需全局排序或 ANN 查询，但不能保证被选中的内容对当前用户一定不相关。

均匀抽槽也不等于在整个簇的全部物品中均匀采样。 碰撞覆盖使一些物品不在池中；反复出现的物品可能更频繁地重新写入，实际驻留分布还受流式数据顺序影响。

5.4 Pre-loading：提高早期命中率

训练开始前，用历史物品特征预加载池，再由训练 Batch 持续更新。这样可以减轻冷启动时的空池问题。

论文说的是提高早期命中率，并没有证明预加载一定填满每个槽。若一个簇的可用物品很少，或 ID 取模集中，预热后仍可能有空槽。

因此，实现时仍要定义无效槽检测、重试次数与回退采样策略。这些是本文提出的工程检查项，不是论文已经公开的实现细节。

5.5 并行运行不自动意味着无冲突或自然去重

论文写到 Update 与 Sample 并行，但未公开完整的内存一致性协议。共享池中，随机读位置仍可能与当前写位置相同；一个当前正样本也可能早已存在于历史池。

所以不能仅根据“更新当前 Batch、读取历史池”推导出：

  • 读写永远不会落到同一个槽；
  • 采样天然排除当前正样本；
  • 同一用户的已知正例无需额外 Mask。

下面是一种便于理解的安全顺序示意，不是论文并行实现的复刻：

真实并行实现可以采用快照、双缓冲、版本检查或其他同步协议，但其成本与正确性需要单独验证，不能冒充论文指定方案。

5.6 O(1) 指定位，不是整个训练流程

单个槽位的索引计算和直接访问可以按 O(1) 分析。但如果 Batch 大小为 B，每个正样本需要 K 个 OOB 候选，那么仅采样请求数就按 BK 增长；特征搬运量、编码计算与用户—物品打分还要另算。

如果每槽特征占 F 字节，忽略元数据，池内存约为 CSF。增大 S 可以减少碰撞压力，但也增加内存和预热成本。

因此，“不依赖全库大小的直接定位”是合理优势，“O(1) 完成所有困难负采样和训练”则是不准确的说法。

6. 公开实验：比较的是同一设置下的采样策略

6.1 评测协议

根据论文 §5.1：

  • 数据集为 MovieLens-1M 和 Amazon Reviews 的 Grocery、Electronics、Home 子集；
  • 按时间排序，前 80% 用于训练，后 20% 用于评估；
  • 评分 1—2 转为负标签，3—5 转为正标签；
  • 不使用 k-core 过滤；
  • 在全局物品库中评估，而不是只与少量随机负样本比较；
  • 同一双塔基础上比较六种采样方法，簇使用现成类别信息。

这解释了为什么其绝对 Hit Rate 可能低于采用强过滤、采样候选的其他实验。指标数值需要连同评测协议阅读，不能跨论文直接排名。

表中的绝对值只有四位小数，用它们直接计算相对增幅可能与论文报告略有出入。例如 0.0050 到 0.0074 按显示值计算为 48%，论文写作 47.3%；本文同时保留原始显示值与报告值，不将二者强行改成精确一致。

还有两个容易混淆的比较：

  1. Amazon-Electronics 的 +55.6% 是相对 In-batch Baseline，不是相对随机 GOOBS；按表中显示值，与随机 GOOBS 相比约提升 19.1%。
  2. 0.0084 到 0.0131 的绝对差为 0.0047，也就是 0.47 个百分点，而不是增加 55.6 个百分点。

在这组已测试配置中，Cluster GOOBS 的 HR@50 与 HR@100 都优于其他对照。但公开结果不能独立证明工业 LLM 聚类的增益，也不能证明它在所有负样本预算或调参条件下都优于 ANCE。

7. 在线实验：+53% 究竟是什么指标？

7.1 场景与对照组

论文 §5.2 描述的是一个大规模社交媒体应用的入口内容发现位置，包含多个召回源。两组各随机选择 3% 用户，实验持续 14 天：

  • Control：双塔 + 随机 GOOBS；
  • Test：相同双塔架构 + Cluster GOOBS。

文中描述了亿级 MAU、千万级可推荐内容和十亿级训练交互的规模，但没有明确点名具体产品。因此不应推测它一定是 Facebook Feed、Reels 或某个特定业务。

7.2 CTR 和效率

指标 论文报告 应如何理解
Source CTR 相对 +53%，p<0.01 被改造召回源所服务曝光的 CTR，不是全系统 CTR
Overall CTR 相对 +6.5% 多召回源整体系统的 CTR 收益
训练 QPS −1.4% 相对随机 GOOBS 的训练吞吐变化
推理 QPS 未观察到退化 该实验中未增加相应服务吞吐负担

+53% 与 +6.5% 是论文分别报告的结果，后者不是由前者简单换算出来的。多召回源之间可能存在候选重叠、流量竞争和下游排序，不能只乘一个流量占比解释全系统收益。

同样，−1.4% 是相对已有随机 GOOBS 的增量开销，不是“从没有 OOB 到整套系统只多花 1.4%”。内容编码、聚类维护与特征池内存也不能因为训练 QPS 接近不变就忽略。

7.3 曝光更分散，但不等于所有偏差都已消除

论文表 3 报告：

指标 Control Test
过去一天曝光至少 1,000 次的物品数量 基准 约增加 50%
Top 100 物品的曝光贡献 50% 32%

第一个指标是达到曝光门槛的物品数量，不能直接写成物品占比或长尾召回率。第二个指标从 50% 降到 32%，是下降 18 个百分点，按相对值为下降 36%。

这些结果支持“曝光覆盖扩大、头部集中度降低”，但不能独立证明长期反馈循环被永久打破，也不能证明每个用户的个性化、多样性或满意度都提升。

8. 如果要复现，优先验证哪些问题？

以下是根据论文机制整理的实施建议，不属于作者已经公开的生产配置。

8.1 先把增量收益拆开

依次对比 In-batch、随机 OOB、类别簇 OOB、内容语义簇 OOB。固定总负样本预算、模型结构、训练数据与训练步数，避免把“负样本更多”误认为“语义聚类更有效”。

也可以分别在固定训练时间下比较质量，从而看清更高质量负样本是否抵偿额外编码与搬运成本。

8.2 同时看困难度和假负例

观察正负分数间隔、负样本 Softmax 概率、梯度范数和训练稳定性；同时统计当前正例重复、用户已知正例命中与语义近重复比例。

论文对簇内假负例较少给出直觉解释，但仅凭“全库很大、用户感兴趣物品较少”，不能推出条件在某个兴趣簇内的假负例率必然很低。兴趣可能恰好集中在这个簇中。

8.3 监控池的真实分布

至少检查：

  • 各簇槽位占用率、空槽命中率和碰撞覆盖率；
  • 特征年龄与物品下架状态；
  • 不同热度物品的写入、驻留与被采样频率；
  • 跨 Batch 重复和用户级已知正例；
  • 聚类版本更新后，槽位中的物品是否仍属于标记的簇。

只监控整体采样 QPS，可能发现不了某些簇几乎没有有效候选，或某些热门物品长期占据特定槽位。

8.4 不把“实时采样”误认为“实时重做 LLM 聚类”

每步训练实时发生的是槽位更新与样本读取。内容编码、中心学习和版本更新有自己的周期；即使新物品能即时分配到已有中心，也不代表整个聚类在每个 Batch 中重新训练。

这一时间尺度分离，正是方案能够以较小训练增量运行的重要条件。

9. 总结：让困难度选择脱离昂贵的全局搜索

Cluster GOOBS 的价值可以概括为三个层次：

  1. 采样机制：用少量同簇负样本增强细粒度竞争，同时保留随机覆盖；
  2. 系统实现：保存物品特征，用按簇分段的有界池支持直接定位、更新和读取；
  3. 实验结果：在公开评测和一个生产系统中取得收益，但需保留聚类来源、基线与指标口径。

它不是一个新的双塔主干，也不是每次训练都调用 LLM 寻找当前最难物品。更准确地说，它把较重的内容理解转化为可重复使用的分组信息，让训练流水线以较低成本持续看到更有竞争力的负样本。

这一思想与 模型与系统协同设计 相通：效果不仅由增加多少计算决定，也由计算被用在何处、训练数据如何被组织决定。
